Module Reference

Detailed specification and role description for each module in the Digital Twin.

01 ☀️

Solar PV Module

What it models
  • Clear-sky irradiance follows the sun: 0 at night, peak at solar noon
  • Cloud factor drifts smoothly (Ornstein–Uhlenbeck) around a daily weather mean
  • Daily weather (Sunny / Partly Cloudy / Overcast) follows a Markov chain
Equations
G(t) = 1000·sin(π(h−6)/12) · k_cloud(t) [W/m²]
P_PV = P_rated · G / G_STC · η_PV (1 W, 1000 W/m², 0.85)
Dataset columns
Solar_IrradianceRenewable_PowerRenewable_AvailabilityWeather
Digital Twin Role

Mirrors a small 1 W IoT solar panel. Its power is time-dependent, never random per minute.

02 🔋

Battery Module

What it models
  • 12 Wh Li-ion pack fed by the PV panel and drained by the ESP32
  • CC/CV charge taper above 90 % SOC, small self-discharge
  • Energy of the chosen action (local or offload) is drawn every minute
Equations
P_net = P_PV − P_load
SOC += η_c·P_charge·Δt / E_bat − P_dis·Δt / (η_d·E_bat)
Dataset columns
Battery_SOCdSOC_dtBattery_Charge_PowerBattery_Discharge_PowerLoad_Power
Digital Twin Role

Closes the loop: decisions change the battery, and the battery SOC changes the price of energy in the next decision.

03 📟

ESP32 IoT Node

What it models
  • One monitoring task per minute: aggregation, filtering, FFT features, anomaly detection or image preprocessing
  • Task_Size = data in the sensing window [KB]; Task_Complexity = CPU cycles per byte
  • 240 MHz core with a background RTOS / WiFi-stack load
Equations
C_required = D_task · c [cycles]
CPU_Load = Background + C / (f_ESP32 · T_deadline) · 100
T_local = C / (f_ESP32 · (1 − Background))
E_local = (P_idle + α·CPU_Load) · T_local
Dataset columns
Task_TypeTask_SizeTask_ComplexityCPU_CyclesCPU_LoadLocal_Exec_TimeLocal_Energy
Digital Twin Role

Heavier tasks raise CPU load, execution time and local energy — the main reason to offload.

04 📶

WiFi / MQTT Network

What it models
  • Node on moving equipment: distance to the access point drifts (3–40 m)
  • Log-distance path loss with correlated shadowing
  • 802.11n rate adaptation (MCS0–7) and packet errors → retransmissions
  • Task sent as an MQTT PUBLISH over TCP/IP (header overhead included)
Equations
RSSI = RSSI_0 − 10·n·log10(d/d0) + X_σ
R_eff = R_MCS · η_MAC · (1 − U_channel) / N_tx
T_tx = Data / R_eff ; T_net = T_tx + T_result + T_gateway + T_queue
E_tx = P_tx · T_tx
Dataset columns
DistanceRSSIWiFi_MCSData_RatePERTransmission_TimeNetwork_LatencyTransmission_Energy
Digital Twin Role

Weak signal → lower MCS and more retransmissions → longer airtime → higher latency and radio energy.

05 🖥️

Edge Server

What it models
  • 3 GHz vCPU shared with other users
  • Daily usage profile plus decaying traffic bursts
  • Processing time grows sharply as utilisation approaches 100 %
Equations
T_edge = C / (f_edge · (1 − U_server)) (M/M/1 sojourn form)
T_offload = T_network + T_edge
Dataset columns
Server_CPU_LoadEdge_Processing_TimeOffload_Total_TimeOffload_Energy
Digital Twin Role

A busy edge makes offloading slower and makes the ESP32 listen longer for the result, so local execution can win.

06 ⚙️

Decision Engine

What it models
  • Computes the physical cost of BOTH options for every task
  • Battery risk raises the price of energy as SOC falls (for both options)
  • No hand-written rules, no random noise: the cheaper option wins
Equations
λ(SOC) = 1 + 4·(1 − SOC/100)^1.5
J_local = λ·E_local/E_ref + T_local/T_dl + 2·[T_local > T_dl]
J_off = λ·E_off/E_ref + T_off/T_dl + 0.3·PER + 0.3·U² + 2·[T_off > T_dl]
Decision = LOCAL if J_local < J_off else OFFLOAD
Dataset columns
Battery_PriceLocal_Execution_CostOffload_Execution_CostDecision
Digital Twin Role

Low SOC + good link → offloading saves energy. Low SOC + poor link → retransmissions make offloading cost more, so local wins.
