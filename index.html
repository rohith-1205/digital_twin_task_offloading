Module Reference

Detailed specification and role description for each module in the Digital Twin.

01 🌱

Renewable Availability Module

Responsibilities
  • Collects real-time solar irradiance & wind speed data
  • Estimates instantaneous power generation (W)
  • Provides renewable availability score (0–1)
  • Forecasts short-term energy availability
Outputs to Decision Engine
P_solar (W) P_wind (W) Irradiance (W/m²) Availability Score
Digital Twin Role

Mirrors a physical renewable energy source — solar panel + wind turbine — and computes net energy generation at every timestep.

02 🔋

Battery Module

Responsibilities
  • Tracks State of Charge (SoC) in real time
  • Models charge/discharge dynamics
  • Enforces safe operating voltage thresholds
  • Estimates remaining operational time
Outputs to Decision Engine
SoC (%) Voltage (V) Discharge Rate Time Remaining
Digital Twin Role

Simulates a LiFePO4 / Li-ion battery pack. When SoC is low and renewables are insufficient, offloading is discouraged to conserve energy.

03 📟

ESP32 Device Module

Responsibilities
  • Generates IoT tasks with size, deadline, and compute demand
  • Reports CPU load, free memory, and power draw
  • Executes tasks locally when instructed
  • Serializes & transmits tasks over WiFi when offloaded
Outputs to Decision Engine
CPU Load (%) Free RAM (KB) Task Size (KB) Deadline (ms)
Digital Twin Role

Emulates a constrained microcontroller. Local execution consumes battery faster; offloading trades energy for compute power.

04 📶

WiFi Network Module

Responsibilities
  • Monitors RSSI, throughput, and round-trip latency
  • Estimates data transfer energy cost
  • Determines if network quality is sufficient for offloading
  • Models packet loss impact on task deadlines
Outputs to Decision Engine
RSSI (dBm) Bandwidth (Mbps) Latency (ms) Transfer Cost (mJ)
Digital Twin Role

Simulates the IEEE 802.11 link between ESP32 and the edge node. Poor signal strength can make offloading more costly than local execution.

05 🖥️

Edge Server Module

Responsibilities
  • Reports available CPU cores, memory, and queue depth
  • Estimates task completion time at the edge
  • Manages incoming task queue from ESP32 clients
  • Returns results back via WiFi
Outputs to Decision Engine
CPU Available (%) Queue Depth Exec Time (ms) Power Cost (mJ)
Digital Twin Role

Simulates a nearby MEC (Mobile Edge Computing) server. If the edge is overloaded, local execution may be preferred even when energy is available.

06 ⚙️

Decision Engine Module

Responsibilities
  • Aggregates telemetry from all 5 input modules
  • Computes a weighted offloading score
  • Enforces renewable-aware policy thresholds
  • Outputs binary decision: LOCAL or OFFLOAD
Decision Formula
Score = α·E_renew + β·(1−SoC_deficit) − γ·WiFi_cost − δ·Edge_load
α = Energy weight β = Battery weight γ = Network weight δ = Load weight
Decision Rule
Score ≥ threshold AND SoC > 30%→ OFFLOAD
Otherwise→ EXECUTE LOCAL
